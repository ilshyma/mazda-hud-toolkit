# Mazda CMU CarPlay-HUD Toolkit

Turn-by-turn navigation from **Apple CarPlay** on the instrument-cluster **Head-Up Display** for Mazda CMU150 (firmware 74.00.324) — with a correct **km/h** speed-limit indicator for the European market.

**Applies to:** CX-5 KF, CX-8, CX-9 (2016-2023) and same-platform units with EU firmware.

**Translations:** [Українська](README.uk.md) · [Español](README.es.md) · [Deutsch](README.de.md) · [Português](README.pt.md)

---

## What this toolkit does

Based on the community-built [KidMixer/mazda-carplay-hud](https://github.com/KidMixer/mazda-carplay-hud) `LD_PRELOAD` shim, with two additions for European vehicles:

1. **km/h fix** — one-line source patch (`displaySpeedUnit = 2` instead of `1`, i.e. VBS enum `km/h` instead of `mph`). Without this fix, an EU HUD renders a `50 km/h` sign coming from the shim as `≈80 km/h` after mile→km conversion.
2. **Speed-limit mirror daemon** — a small shell script that passively watches the OEM `svcjcinavi.so` HUD stream and copies the *current* speed limit into the shim's own keep-alive frames. Without this, the shim overwrites the speed slot with `0` every 500 ms and the value dies to `---` between OEM updates.

Everything else is bit-for-bit the original KidMixer build.

## Requirements

- Mazda CMU150, firmware `74.00.324`, EU flavor (verify: `cat /jci/version.ini` on CMU)
- USB flash drive (≥1 GB, FAT32-formatted)
- A computer with Wi-Fi (macOS, Linux, or Windows 10+)
- Wi-Fi hotspot on your CMU (comes with wireless-CarPlay dongles) or the working root+SSH setup described below

## Menu (both `toolkit.sh` and `toolkit.bat`)

| # | Action |
|---|---|
| **1** | **Create USB stick** — formats a USB drive (FAT32, label MZD) with the MP3-XSS unlock (SSH button) **and** the HUD patch (`hud-mod/`). In the car the on-screen menu offers **SSH**, **HUD+** (install), **HUD-** (remove) and **HUD?** (check), so the patch can be installed without a laptop. |
| **2** | **Backup CMU** — SSH-fetches an archive of every file a patch touches into `backups/YYYYMMDD_HHMMSS/`. Run this before installing. |
| **3** | **Rollback** — removes **every** HUD patch: CarPlay + Android Auto, ilshyma v16 with its speed daemon, KidMixer and oem-aa-mod. Returns to stock, reboots and confirms. |
| **4** | **Install HUD patch (CarPlay + Android Auto)** — one patch for both phones: arrows and distance for CarPlay and Android Auto, and the speed-limit sign from the stock navigation (needs the nav SD card). Every file is md5-verified. The toolkit reboots the unit, waits for SSH and checks that all 4 parts loaded. Source: [mazda-carplay-hud `unified-carplay-aa`](https://github.com/ilshyma/mazda-carplay-hud/tree/unified-carplay-aa). The street-name line does not show on EU HUDs. |
| **B** | **Bootstrap SSH key** — one-time setup for the SSH flow (options 2 / 3 / 4). Generates `id_rsa_cmu` if missing and installs its public half into the CMU's `authorized_keys` using the one-time password `cmu:jci` baked by the USB XSS unlock. Needed only on a new computer. |
| **A** | **Advanced** — validate the installation, SSH check, diagnostic dump, and the older CarPlay-only patches (v16, pure KidMixer, legacy) with their tools. |


### Installing the HUD patch from the USB stick (no laptop)

The stick from option 1 also carries the CarPlay + Android Auto HUD patch (`hud-mod/`). In the car, open it the usual way: Media → USB → tap an mp3. The menu at the top of the screen has three extra buttons:

- **HUD+** installs the patch. Tap it, then tap the red confirmation button. The unit reboots by itself after about 30 s.
- **HUD-** removes it, back to stock. Confirmed the same way.
- **HUD?** checks that every part is active: CarPlay, Android Auto, Navi/speed.

Every button ends with a message on the screen. If it starts with **ERROR** or **CHECK S1**, take a photo of it and send it. It carries an error code, the firmware version, the region and what to do next. Every attempt gets its own numbered folder on the stick, `hud-mod/logs/001_install_<date>/`, with the same text (`RESULT.txt`), the full log (`run.log`) and a system snapshot (`system.txt`). Send that folder together with the photo.

## Two ways to install

| | **A. USB-only** _(default — nothing to type)_ | **B. SSH install from your computer** |
|---|---|---|
| What you do in the car | Insert the stick → tap **Install** on the dialog. | Insert the stick → tap **SSH** in the XSS menu. |
| What runs on the CMU | Patch is installed automatically from the USB. | A tiny `sshd` starts on `192.168.53.1:36000`. |
| What you do on your computer | Nothing. | Run **options 2 / 4** of this toolkit over SSH. |
| Needs the SSH key? | No. | Yes — generate it once with option **B** below. |
| Needs the USB stick? | Yes, every install. | Yes, once per CMU boot (to turn SSH back on — the CMU kills `sshd` on reboot). |

Pick A if you just want the HUD mod. Pick B if you also want backups, auto-validation, diagnostics or the older CarPlay-only variants (menu `L` / `P` / `X`).

### A. USB-only (recommended for most users)

1. Run **option 1** on your computer — this creates the USB stick.
2. Insert the stick in the car — wait ~30 s. A dialog with **Install / Uninstall / Check Status** appears automatically (CMU reflash scanner is hooked via `.up` payloads). If nothing shows up: Media → USB → tap any mp3 — the XSS fallback menu has **HUD+ / HUD- / HUD?** buttons.
3. Tap **Install**. The screen goes dark for ~2 min while the unit reboots — this is normal, don't turn off the ignition.
4. Done. Start a CarPlay or Android Auto navigation session; the arrow should appear on the HUD.

### B. SSH install from your computer (power users)

1. **Create the USB stick** — run **option 1**.
2. **Enable SSH on the CMU** — insert the stick in the car, Media → USB → tap any mp3 → tap **SSH** in the XSS overlay. Log messages appear. (sshd is now listening on `192.168.53.1:36000`. It gets killed on every boot — repeat this step after each restart.)
3. **Join the CMU Wi-Fi** on your computer (`CMU-XX:XX:...` or `MAZDA-xxx`).
4. **Bootstrap the SSH key — once per computer:** run **option B**. The toolkit generates `id_rsa_cmu`, pushes the public half to the CMU using the one-time password `jci`, and verifies key-based login. You'll be prompted for the password exactly once.
5. **Verify + back up** — Advanced → **S** (SSH check), then **option 2** (backup).
6. **Install** — run **option 4**. Every file is md5-verified, the CMU reboots, the toolkit waits for SSH to come back and auto-validates all 4 shims. (After the reboot, redo step 2 so SSH is up for the validate step — the toolkit will prompt and wait.)
7. **Test** — start a CarPlay or Android Auto navigation session. The maneuver arrow should appear on the HUD; the speed-limit slot should show the current OEM value (from map + TSR camera).

> **The SSH key is NOT shipped** — the public release has no `id_rsa_cmu`. Option **B** creates it locally and installs it on the CMU. The private key never leaves your computer; the CMU side keeps the public half in `/data_persist/.../authorized_keys` so it survives reboots.

## Notes and limitations

- The shim uses `LD_PRELOAD` only — the OEM `blmjcicarplay.so` is *never* modified on disk. The read-only rootfs cannot be bricked; worst case, a reboot returns the unit to stock.
- The speed-mirror daemon does **not** trigger any NNG requests. It only listens to what the OEM navigation service (`svcjcinavi.so`) already broadcasts on the D-Bus service bus. So the HUD stays as close to stock behaviour as possible.
- Lane guidance arrows (`SetRecommLaneReq`) are **not** implemented — Apple does not transmit lane data over the iAP2 side channel; only the CarPlay video stream carries it.
- Cyrillic street names render correctly; the Ukrainian apostrophe (`’`) currently prints as `?` because the OEM HUD font lacks that glyph — this is an OEM limitation.
- The build was made with `-DCARPLAY_VN_NORMALIZE=1` (Vietnamese diacritic stripping for the HUD font). Harmless on Cyrillic/Latin.

## Under the hood

- Base shim: **KidMixer/mazda-carplay-hud v2.0.0** — [source](https://github.com/KidMixer/mazda-carplay-hud), AGPL-3.0.
- One source change on top: `hud/hud_send.cpp` line 561, `displaySpeedUnit` value `1 → 2` (VBS enum: `1 = mph`, `2 = km/h`).
- Speed-mirror daemon: our own ~60-line shell script; passively watches `com.jci.vbs.navi.SetHUDDisplayMsgReq` calls whose sender is *not* our own shim, and writes `<km/h> <unix_ts>` to `/data_persist/splim`. Rebuilt every 3 s to keep the shim's stale-check happy; TTL 3600 s so a genuine dead-zone longer than an hour clears the value.
- The shim reads `/data_persist/splim` on every keep-alive frame; if fresh, includes the value; if empty/stale, sends `0` (behaving like the stock installer's build).

## Windows: `toolkit.bat` throws parser errors? Use Git Bash instead

If `toolkit.bat` on Windows spits out `'t' is not recognized`, `Missing expression after ','`, `cannot find batch label` or similar — the file is being parsed by `cmd.exe` in a way that chokes on some Windows builds. The toolkit itself is fine; the fastest workaround is to run `toolkit.sh` through Git Bash:

1. Install **Git for Windows** — https://git-scm.com/download/win (one click, ~50 MB).
2. Open **Git Bash** from the Start menu.
3. `cd` into the toolkit folder, e.g. `cd /c/Users/<you>/Downloads/mazda-hud-toolkit/mazda-hud-toolkit`
4. Run: `bash toolkit.sh`

Everything except **Create USB stick** (option 1) works end-to-end through Git Bash — backup, install, rollback, validate, Bootstrap SSH key. For the USB-create step either use `toolkit.bat` option 1 on the same Windows machine, or format the stick manually (FAT32, label `MZD`) and copy `files/usb_unlock/` + `files/unified/` → `hud-mod/` to it.

## Support

If SSH refuses to connect on port 36000, the `sshd` on the head unit was killed by the read-only rootfs at boot. Re-run the USB → XSS → SSH step and it comes back up.

If password-based bootstrap (**option B**) says *"Permission denied"*, the password is wrong. The USB XSS unlock sets `cmu:jci` — type `jci` (lowercase, three letters) at the prompt. If it still fails, the USB didn't fire — redo step 2 (USB → XSS → SSH) and retry B.

If the HUD stays blank after install, verify with Advanced → **V** first; then SSH in and check `ps | grep sm_svclauncher | grep jciCARPLAY` — the `L_jciCARPLAY` process must be running with `LD_PRELOAD` in its `/proc/PID/environ`.
