Mazda HUD Toolkit
CMU150 · FW 74.00.324 · EU

Apple CarPlay turn-by-turn on the Mazda HUD.

A polished, tested build of KidMixer's community shim with a one-line source patch that fixes the km/h indicator for European vehicles — and a small daemon that keeps the speed slot alive between OEM updates.

Download toolkit → 340 KB · macOS · Linux · Windows 10+

01What it does

Adds the CarPlay maneuver + distance overlay to your instrument-cluster HUD, exactly like the built-in native navigation. Two additions on top of the community KidMixer/mazda-carplay-hud build:

  • km/h fix. The shim was written with displaySpeedUnit = 1 which the VBS enum reads as mph. On an EU HUD that renders a 50 km/h sign as ≈80 after mile→km conversion. Our fix flips it to 2 (km/h).
  • Speed-limit mirror daemon. A small shell script that passively watches the OEM svcjcinavi.so HUD stream and copies the current value into the shim's keep-alive frames. Without it the shim overwrites the speed slot with 0 every 500 ms and the value dies to --- between OEM updates.

Everything else is bit-for-bit the KidMixer original.

02Requirements

  • Mazda CMU150, firmware 74.00.324, EU flavor (verify: cat /jci/version.ini)
  • USB flash drive (≥ 1 GB, FAT32-formatted)
  • A computer with Wi-Fi (macOS, Linux, or Windows 10+)
  • CMU Wi-Fi hotspot (usually comes with a wireless-CarPlay dongle)

03Menu options

Both toolkit.sh (macOS / Linux) and toolkit.bat (Windows 10+) show the same numbered menu.

1

Create USB unlock stick

Wipes and formats a USB stick as FAT32 with the label MZD, then copies the MP3-XSS payload that opens root+SSH on the CMU. Insert the stick in the head unit, tap any MP3, then tap SSH in the XSS overlay — sshd starts on port 36000.

2

Backup CMU state

Downloads every file the installer touches (sm.conf, sm_WCP.conf, devmgr_config_master.xml, blmjcicarplay.so, /data_persist/cp-hud-mod/, version.ini) as a tar.gz into backups/YYYYMMDD_HHMMSS/. Run this before installing anything.

3

Install KidMixer patch

Three-step deploy: (a) runs the vanilla install.sh which adds the LD_PRELOAD line to sm.conf and sets NaviSupported=TRUE, (b) overlays our km/h-fixed .so, (c) drops in the speed-mirror daemon and its auto-launcher. Ends with a reboot; wait ~2 min then re-establish SSH via the USB stick.

4

Full rollback

Kills our daemon, removes our extras, runs the vanilla uninstall.sh which restores sm.conf and NaviSupported=FALSE from the .bak_precphud backups made by install.sh. Ends with a reboot.

04First-time procedure

Format a USB stick, run option 1 to prepare it.
Insert the stick in the car. Media → USB → tap any MP3 → wait for the XSS overlay at the bottom of the screen → tap SSH. Green log lines appear, done.
Connect your computer to the CMU Wi-Fi (CMU-XX:XX:... or MAZDA-xxx).
Run option 9 to verify SSH works, then option 2 to back up.
Run option 3 to install. Wait for reboot.
On the head unit, repeat step 2 (USB → SSH) to re-enable SSH after the reboot.
Start a CarPlay navigation session. The maneuver arrow appears on the HUD; the speed-limit slot shows the current OEM value from map + TSR camera.

05Notes and limitations

Cannot brick the head unit. The shim uses only LD_PRELOAD — the OEM blmjcicarplay.so is never modified on disk. The read-only rootfs guarantees a reboot always returns the unit to a working state.

  • The daemon does not trigger any NNG requests. It only listens to what the OEM navigation service already broadcasts on D-Bus, so the HUD stays as close to stock behaviour as possible.
  • Lane guidance arrows (SetRecommLaneReq) are not implemented — Apple does not transmit lane data over iAP2, only in the CarPlay video stream.

06Support

If SSH refuses to connect on port 36000, the sshd on the head unit was killed by the read-only rootfs at boot. Re-run the USB → XSS → SSH step and it comes back up.

If the HUD stays blank after install, verify with option 9 first, then SSH in and check ps | grep sm_svclauncher | grep jciCARPLAY — the L_jciCARPLAY process must be running with LD_PRELOAD in its /proc/PID/environ.
